## LYLX: the ground-up intelligence program

**LYLX by The Donald Company** is the new integrated architecture. Its design
keeps responsibilities explicit:

| Component | Intended responsibility |
| --- | --- |
| **Quesar** | The largest shared foundation model in the LYLX family. |
| **Abbey / Aviva** | Consolidated personalities trained or adapted on Quesar: Abbey is the primary collaborator; Aviva is the candid, direct expert mode. |
| **ABI** | Dynamic moderation, routing, context selection, and authorized execution. |
| **WDBX 3D** | The neural memory/storage database, combining durable records, spatial and semantic representations, graphs, specimens, and provenance. |

LYLX is a ground-up development direction, not a claim that the existing
repositories have already been replaced or that a production Quesar checkpoint
has been trained. Historical source, data formats, and conformance evidence
remain valuable references. The Quesar model and the `quesar.cloud` website are
not the same deliverable.

Aviva's expressive latitude changes conversational style, not data access,
consent, factual standards, or permission to execute tools. Small-model image
and video generation and evaluated self-improvement belong to the research
program; their availability must be established by actual implementations,
checkpoints, and evaluations.

## NYON's direction

NYON is **creative-first**, with optional Survival and procedural Geometry Nodes
in its broader direction. Existing Rust simulation and save contracts remain
important. Roadmap goals are not shipped-feature claims, and NYON is not being
recast as an AI model subsystem.

## Build with evidence

We distinguish design, implementation, tests, measured performance, and deployed
behavior. A successful build does not prove a hardware speedup, a generated
dataset does not prove trained weights, and a website showcase is not a model
benchmark.

To contribute, start with the relevant repository's README and `AGENTS.md` or
contribution guide, preserve existing data and compatibility, and submit a
focused change with reproducible checks. Use that repository's issue tracker
for questions; never include credentials or private memory in a public report.

Licensing is repository-specific. Read the applicable license before using or
redistributing code, model artifacts, data, or media.
